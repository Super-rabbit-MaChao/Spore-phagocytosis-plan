# 《孢子进化》核心玩法系统设定文档

## 一、文档定位

本文档用于整理《孢子进化》的核心玩法方向。

当前游戏不再采用“纯前端 + JSON 实时读取存档”的方式，而是转向**正常游戏开发模式**。也就是说，游戏可以使用 Godot、Unity 或其他正式游戏引擎开发，采用完整的游戏项目结构，包括场景、对象、系统管理器、资源配置、存档系统、UI 系统、动画表现、音效表现等。

本文档重点描述：

- 游戏核心玩法
- 翻格子地图机制
- 微生物角色移动与蔓延
- 培养皿休整系统
- 地图内进化系统
- 孢子化系统
- 地图难度与资源机制
- 正常游戏开发模式下的系统拆分
- 第一版 MVP 开发建议

---

# 二、游戏核心定位

## 1. 核心玩法类型

游戏可以定义为：

```text
翻格子探索 + 微生物菌群扩张 + 培养皿养成 + 地图内进化
```

玩家不是控制传统人形角色，而是控制一个“微生物核心菌落”。

核心菌落进入地图后，会随机落在某个六边形格子上，周围相邻格子自动揭示。玩家通过翻格、移动、采集、蔓延、进化、孢子化等操作，在不同生态地图中生存和扩张。

画面采用 2D 俯视、科普绘本风；角色以菌落图标表现，核心菌落与蔓延菌落通过背景颜色等视觉手段区分。

## 2. 参考玩法感觉

操作节奏可以参考“不可思议的迷宫”一类的翻格探索体验：

```text
未知格子
  ↓
玩家翻开
  ↓
发现资源 / 危险 / 敌人 / 事件 / 传播格
  ↓
做出移动、采集、蔓延或孢子化撤离选择
```

但本游戏的主题不是冒险者探索地牢，而是微生物在生态环境中演化、扩散和适应。

# 三、核心游戏循环

## 1. 总体循环

```text
培养皿中选择微生物
  ↓
投喂资源，恢复族群
  ↓
选择地图
  ↓
随机落入安全格
  ↓
周围一圈自动揭示
  ↓
翻格探索
  ↓
收集资源
  ↓
移动或蔓延
  ↓
遭遇环境压力
  ↓
触发进化机会
  ↓
积累能量与成果后孢子化撤离 / 探索失败
  ↓
带回资源、孢子和部分进化成果
  ↓
回到培养皿休整
```

说明：

```text
地图没有固定通关条件。
玩家以获取资源、触发进化、制造孢子为目的进入地图，
达到收益后通过孢子化撤离，或因失败结算返回培养皿。
```

## 2. 核心设计逻辑

| 场景 | 作用 |
|---|---|
| 培养皿 | 安全休整、缓慢繁衍、投喂资源、准备出征 |
| 地图 | 探索、获取资源、承受压力、触发进化、传播孢子（进化场，非一次性关卡） |

## 3. 成长逻辑

| 成长方式 | 发生地点 | 说明 |
|---|---|---|
| 繁衍恢复 | 培养皿 / 地图 | 增加族群数量 |
| 资源积累 | 培养皿 / 地图 | 用于投喂、技能、繁殖、出征 |
| 进化变异 | 只能在地图 | 需要环境压力、特殊资源或事件触发 |
| 孢子继承 | 地图结束时 | 带回部分成果，支撑下次探索 |

核心原则：

```text
培养皿安全，但成长有限。
地图危险，但可以真正进化。
```

# 四、场景系统

## 1. 培养皿场景

培养皿是玩家的主基地。

角色不在地图中时，会待在培养皿里。培养皿可以让微生物按**真实时间**缓慢繁衍恢复，但有上限，并且不能发生进化。

### 培养皿功能（第一版）

| 功能 | 说明 |
|---|---|
| 角色休整 | 微生物返回后停留在培养皿 |
| 真实时间恢复 | 按现实时间自动恢复各角色族群数量 |
| 投喂资源 | 无配方；直接消耗该角色已分配资源，立即补充族群 |
| 资源分配 | 地图带回资源先进公共库存，由玩家手动分配给各角色；**角色间不共享** |
| 出征准备 | 选择角色、地图，从该角色已分配资源中携带入场 |
| 孢子复苏 | 使用该角色孢子库存恢复族群或辅助出征 |

### 培养皿限制（第一版）

| 限制 | 设计目的 |
|---|---|
| 有繁衍上限 | 防止玩家无限积累 |
| 不能进化 | 保证地图探索的重要性 |
| 无升级 | 第一版暂不支持培养皿升级 |
| 无配方 | 降低系统复杂度，投喂即扣对应资源 |
| 恢复速度较慢 | 保留探索失败的时间代价 |

推荐规则：

```text
培养皿按真实时间自动恢复各族群，恢复到该角色族群上限。
公共库存需玩家手动分配到角色后，该角色才能用于投喂或出征携带。
想要变强，必须进入地图承受环境压力并成功撤离以固化进化。
```

### 真实时间恢复默认值

| 项目 | 默认 |
|---|---|
| 恢复节奏 | 每现实 10 分钟 +1 族群 |
| 离线累计 | 允许，设每日恢复上限（第一版建议最多恢复至上限的 50% 缺口） |
| 投喂 | 每消耗 5 营养立即 +1 族群（可再调） |
## 2. 地图场景

地图是主要玩法区域，定位为可反复进入的**进化场**，而不是一次性关卡。

地图由六边形格子组成。每张地图有自己的环境参数、资源分布、危险事件、敌人种类和进入限制。

**每次进入地图都会重新生成布局。** 生成后本局资源点固定，采集后减少/清空，局内不再额外刷新再生。跨局保留的是地区长期变量（解锁、图鉴、生态印象等），不是具体格子布局。

玩家进入地图的主要目的是获取资源、承受环境压力、触发进化、制造孢子；没有强制通关条件，随时可尝试孢子化撤离。

### 地图核心元素

| 元素 | 说明 |
|---|---|
| 格子 | 地图的基本单位（六边形） |
| 迷雾 | 未探索区域 |
| 资源 | 水分、营养、糖分、矿物质、基因点等 |
| 危险 | 干旱、毒素、酸碱、高温、低温等 |
| 敌人 | 竞争菌群、捕食者、免疫单位等 |
| 传播格 / 出口格 | 提供传播机会、撤离加成或进入新地图的入口，不是强制通关点 |
| 事件 | 干旱周期、消毒事件、藻华、腐败倒计时等 |

# 五、格子地图系统

## 1. 地图开局规则

玩家进入地图后，系统执行以下流程：

```text
1. 根据地图难度生成格子地图
2. 随机选择一个安全格作为初始落点
3. 核心菌落落在该格子上
4. 当前格子自动揭示
5. 周围一圈格子自动揭示
6. 玩家开始第一回合操作
```

## 2. 初始揭示范围

地图使用六边形格子。开局建议揭示核心格及其 6 个相邻格：

```text
  □ □
□ 菌 □
  □ □
```

说明：

- 中间是核心菌落所在格。
- 周围 6 个相邻六边形格自动揭示。
- 揭示后可能看到资源、危险、空格、敌人或事件。
- 不建议开局只显示 1 格，否则选择过少。
- 不建议开局显示太大，否则翻格探索感下降。

## 3. 格子状态

| 状态 | 说明 |
|---|---|
| 未知 | 尚未翻开，玩家不知道内容 |
| 已揭示 | 已翻开，但未被占领 |
| 已占领 | 被玩家菌群蔓延覆盖 |
| 资源格 | 存在可采集资源 |
| 危险格 | 存在环境压力 |
| 敌人格 | 存在竞争者或捕食者 |
| 事件格 | 触发特殊事件 |
| 传播格 / 出口格 | 提供传播机会、撤离加成或进入新地图，不是强制通关条件 |

## 4. 格子内容概率

资源不能每一格都有，否则探索没有紧张感。

第一版可以采用如下概率：

| 格子内容 | 建议概率 |
|---|---:|
| 空格 | 35% |
| 普通资源 | 30% |
| 危险环境 | 15% |
| 敌人 / 竞争者 | 10% |
| 特殊事件 | 7% |
| 稀有进化资源 | 3% |

不同地图可以调整概率。

# 六、核心菌落与蔓延菌群

## 1. 角色表现方式

建议将玩家控制对象拆成两层：

```text
核心菌落 = 玩家主要控制对象
蔓延菌群 = 玩家扩张出去的占领区域
```

这样可以避免控制逻辑混乱。

## 2. 核心菌落

核心菌落相当于玩家的“主角”。

| 属性 | 说明 |
|---|---|
| 位置 | 位于某一个格子 |
| 可移动 | 可以移动到相邻已揭示格 |
| 可采集 | 可以主动采集当前格资源 |
| 可翻格 | 可以翻开相邻未知格 |
| 可进化 | 满足条件时可以在地图中进化 |
| 可孢子化 | 可以进入休眠、撤离或传播状态 |
| 可死亡 | 核心菌落死亡则本次探索失败 |

## 3. 蔓延菌群

蔓延菌群代表微生物向周围扩张形成的占领区域。

| 属性 | 说明 |
|---|---|
| 位置 | 分布在已占领格子中 |
| 作用 | 占地、采集、防御、连接资源 |
| 形成方式 | 消耗族群数量、能量或营养 |
| 风险 | 可能被敌人、环境事件或消毒清除 |
| 限制 | 通常需要与核心菌落或已有占领格相邻 |

## 4. 移动和蔓延的区别

这是本玩法最重要的规则之一。

| 行为 | 控制对象 | 作用 | 主要消耗 |
|---|---|---|---|
| 移动 | 核心菌落 | 探索、转移、逃离危险 | 能量 / 行动点 |
| 蔓延 | 蔓延菌群 | 占领、采集、防御、扩张范围 | 族群 / 营养 / 能量 |
| 翻格 | 核心菌落 | 获取地图信息 | 行动点 |
| 采集 | 核心菌落或占领格 | 获得资源 | 行动点 / 时间 |
| 孢子化 | 核心菌落或菌群 | 保命、撤离、传播 | 大量能量 / 族群 |

推荐规则：

```text
核心菌落负责探索。
蔓延菌群负责占领。
```

# 七、回合与行动系统

## 1. 回合制结构

采用回合制。

每一回合分为：

```text
玩家行动阶段
  ↓
地图结算阶段
```

### 行动点规则

| 项目 | 规则 |
|---|---|
| 初始行动点 | 每回合 3 点 |
| 单次消耗 | 每个动作消耗 1 点行动点 |
| 行动点变化 | 可随进化增加，也可因异常状态减少 |
| 资源消耗 | 不同动作额外消耗不同资源（能量、营养、族群等） |
| 阶段切换 | 行动点归零或玩家主动结束后，进入地图结算阶段 |

### 玩家行动阶段

玩家在每回合内消耗行动点执行多个操作。

| 行动 | 说明 |
|---|---|
| 翻格 | 翻开一个相邻未知格 |
| 移动 | 移动到相邻已揭示格 |
| 采集 | 采集当前格或占领格资源 |
| 蔓延 | 将菌群扩张到相邻格 |
| 进化 | 满足条件时选择进化 |
| 孢子化 | 进入休眠、撤离或传播状态（主动退出地图的主要方式） |
| 使用资源 | 消耗携带资源恢复或强化 |
| 撤离 | 通过孢子化撤离；在传播格上可获得撤离加成或传播机会 |

### 地图结算阶段

玩家行动后，地图进行一次结算。

| 结算内容 | 说明 |
|---|---|
| 资源刷新 | 局内不再生；仅处理事件导致的一次性资源变化 |
| 敌人行动 | 敌人移动、攻击或扩张 |
| 环境变化 | 干旱、水流、毒素、温度变化 |
| 菌群消耗 | 按难度与环境成比例消耗能量和水分 |
| 危险扩散 | 毒素、干燥、污染等扩散 |
| 事件倒计时 | 腐败、消毒、免疫反应等推进 |

# 八、资源系统

## 1. 基础资源

| 资源名 | 作用 |
|---|---|
| 能量 | 移动、技能、维持生命活动 |
| 水分 | 维持细胞活性 |
| 营养 | 繁殖、蔓延、恢复族群 |
| 糖分 | 酵母菌等角色的高效繁殖资源 |
| 矿物质 | 防御、抗性、特殊进化 |
| 基因点 | 解锁进化节点 |
| 孢子数 | 撤离、复苏、继承、传播 |

## 2. 地图资源来源

| 来源 | 说明 |
|---|---|
| 普通资源格 | 翻开后可采集；采空后本局不再生 |
| 敌人残骸 | 击败竞争者后获得（一次性） |
| 地图事件 | 例如雨水、腐败、组织液释放（事件触发的一次性变化） |
| 稀有进化格 | 获取基因点或特殊材料 |
| 传播格 / 撤离加成 | 在传播格孢子化撤离时可获得额外收益或进入新地图机会 |

说明：第一版取消“占领格持续产出”，避免变相局内刷资源。

## 3. 资源生成原则

```text
每次进入地图重新生成资源布局。
生成后本局资源点不再额外刷新再生。
稀有资源生成权重低。
地图危险与事件仍会随回合推进。
```

这样可以避免同一局里无限刷资源，同时保留“反复进入不同随机布局”的探索感。

# 九、进化系统

## 1. 进化发生地点

进化只能在地图中发生。

培养皿中只能繁衍和恢复，不能进化。

原因：

```text
进化需要环境压力、资源竞争和生存挑战。
培养皿太安全，不提供真正的自然选择压力。
```

## 2. 临时进化与永久进化（已确认）

| 类型 | 规则 |
|---|---|
| 临时进化 | 在地图中解锁后本局立即生效 |
| 永久进化 | 必须成功孢子化撤离后，才把本局临时进化固化到角色 |
| 失败 / 未撤离 | 本局临时进化全部丢失 |
| 进化失败 | **不存在**；不同环境只改变进化资源消耗 |
| 异常状态变异 | 第一版不做 |

## 3. 进化触发来源

| 来源 | 示例 |
|---|---|
| 环境压力 | 经历干旱后解锁耐干燥 |
| 资源积累 | 收集矿物后解锁厚壁强化 |
| 危机触发 | 族群低于一定比例后解锁休眠路线 |
| 特殊格子 | 发现古老孢子、基因碎片、突变源 |
| 地图事件 | 扛过消毒事件后获得抗毒进化 |
| 敌人压力 | 与竞争菌群对抗后解锁攻击或防御路线 |

## 4. 进化方向

| 方向 | 作用 |
|---|---|
| 生存进化 | 提高抗干燥、抗毒、抗温度变化 |
| 繁殖进化 | 提高族群恢复和扩张速度 |
| 代谢进化 | 利用更多资源类型 |
| 移动进化 | 提高探索和撤离能力 |
| 群体进化 | 强化蔓延、生物膜、分工 |
| 孢子进化 | 提高孢子抗性、传播和继承能力 |

## 5. 进化消耗与环境

进化消耗随环境变化，不存在失败判定。

| 情况 | 消耗 |
|---|---|
| 角色主场环境 | 更便宜（系数约 0.8） |
| 普通环境 | 标准消耗 |
| 逆环境 | 更贵（系数约 1.5） |

## 6. 进化解锁示例

| 挑战 | 可解锁进化 |
|---|---|
| 在干旱中存活 5 回合 | 耐干燥 |
| 在毒素格中存活 3 回合 | 抗毒 |
| 连续占领 5 个水域格 | 漂浮传播 |
| 被免疫单位追击后存活 | 抗免疫 |
| 在水果腐败加剧前成功孢子化撤离 | 快速发酵 |
| 扛过一次高温事件 | 耐热 |
| 孢子化后成功复苏 | 快速复苏 |

# 十、孢子系统

## 1. 孢子系统定位

孢子系统不是完整的进化系统，而是进化系统中的重要分支，同时承担生存、撤离、传播和继承功能。

```text
微生物进化 = 长期成长路线
孢子系统 = 生存、传播、继承机制
孢子化撤离 = 退出地图并保存成果的主要方式
```

地图没有固定通关条件时，孢子化的重要性进一步提高：它既是保命手段，也是正常探索结束流程。

## 2. 孢子的主要用途

| 用途 | 说明 |
|---|---|
| 保命 | 环境恶劣时进入休眠，避免灭绝 |
| 撤离 | 带着部分成果离开地图 |
| 传播 | 通过风、水流、昆虫、食物等进入新地图 |
| 继承 | 保留部分资源、进化或族群种子 |
| 复苏 | 在合适条件下重新成长 |

## 3. 孢子状态

| 状态 | 效果 |
|---|---|
| 活跃菌落 | 可以移动、采集、蔓延、进化 |
| 孢子化中 | 消耗资源和回合，将族群转为孢子 |
| 休眠孢子 | 不能移动和采集，但抗性极高 |
| 传播孢子 | 可以通过传播格或事件进入新地图 |
| 复苏菌落 | 消耗资源重新恢复为核心菌落 |

## 4. 孢子属性

| 属性 | 作用 |
|---|---|
| 耐热 | 抵抗高温、发烧、消毒 |
| 耐寒 | 抵抗冰川、冻土 |
| 耐干燥 | 抵抗土壤干旱、皮肤环境 |
| 耐酸 | 抵抗胃部、酸性环境 |
| 抗毒 | 抵抗污水、化学物质 |
| 漂浮性 | 提高水流、空气传播成功率 |
| 附着性 | 提高落地后存活率 |
| 复苏速度 | 提高进入新地图后的恢复效率 |
| 遗传稳定 | 提高进化能力继承比例 |

# 十一、地图难度系统

## 1. 地图难度定义

地图难度不是单纯的敌人等级，而是多种环境压力的组合。

| 参数 | 说明 |
|---|---|
| 温度压力 | 高温或低温 |
| 干燥压力 | 水分消耗速度 |
| 毒性压力 | 持续伤害或属性削弱 |
| 酸碱压力 | 对不耐酸碱角色造成伤害 |
| 敌人强度 | 竞争菌群或捕食者等级 |
| 资源稀缺度 | 生成时的资源数量与分布（局内不再生） |
| 地图事件强度 | 干旱、腐败、消毒等事件频率 |
| 撤离难度 | 孢子化能量门槛受体量影响；传播格数量与危险环境对撤离的干扰 |
| 难度系数 | 放大行动消耗与每回合维持消耗 |

## 2. 地图进入限制

| 地图 | 推荐进入条件 |
|---|---|
| 土壤 | 无限制，新手地图 |
| 淡水池塘 | 推荐拥有基础移动或漂浮能力 |
| 腐烂水果 | 推荐拥有糖分利用或快速繁殖能力 |
| 人体 | 推荐拥有耐酸、黏附或抗免疫能力 |
| 污水管道 | 推荐拥有抗毒或生物膜能力 |
| 极端环境 | 需要耐热、耐寒、耐盐、耐酸等高级抗性 |

# 十三、正常游戏开发模式说明

## 1. 不再采用纯前端思路

原本如果使用纯前端，可能会将角色、地图、存档、事件全部放在 JSON 中，通过页面逻辑直接读取和展示。

现在改为正常游戏开发模式后，建议采用以下结构：

```text
游戏引擎
  ↓
场景系统
  ↓
角色对象
  ↓
地图生成系统
  ↓
回合系统
  ↓
资源系统
  ↓
进化系统
  ↓
存档系统
  ↓
UI / 动画 / 音效表现
```

这意味着：

- 角色不只是 JSON 数据，而是游戏对象。
- 地图不只是数组，而是格子节点或瓦片系统。
- 存档不只是前端 localStorage，而是正式存档文件或平台存档。
- 技能和进化不只是按钮逻辑，而是由系统统一管理。
- 表现层和逻辑层要分开。

## 2. 推荐技术路线

### 方案 A：Godot

适合个人或小团队开发。

| 优点 | 说明 |
|---|---|
| 轻量 | 上手相对快 |
| 2D 友好 | 适合格子地图、翻格探索 |
| 资源系统灵活 | 可以用 Resource 管理配置 |
| 脚本简单 | GDScript 类似 Python，较容易理解 |

适合本项目的原因：

```text
本游戏偏 2D、格子、回合制、系统驱动。
Godot 比较适合快速做原型。
```

### 方案 B：Unity

适合后期想做更完整商业化表现。

| 优点 | 说明 |
|---|---|
| 生态成熟 | 插件、教程、资源多 |
| 2D/3D 都能做 | 后期扩展空间大 |
| ScriptableObject 适合配置 | 可管理角色、技能、地图数据 |
| 发布平台多 | PC、移动端都方便 |

适合本项目的原因：

```text
如果你希望后期做更完整 UI、动画、特效和多平台发布，Unity 更稳。
```

### 方案 C：Unreal

不建议作为本项目第一选择。

原因：

```text
本游戏目前核心是 2D 格子策略和系统设计，不需要高规格 3D 表现。
Unreal 对这个项目来说偏重。
```

# 十五、数据配置方式

虽然不再是纯前端，但仍然建议保持“数据驱动”。

也就是说，角色、地图、技能、资源、事件等配置应该尽量放在可编辑数据中，而不是全部硬编码。

## 1. 配置内容

| 配置类型 | 示例 |
|---|---|
| 角色配置 | 芽孢杆菌、蓝细菌、酵母菌等基础属性 |
| 技能配置 | 芽孢化、光合作用、出芽繁殖等 |
| 地图配置 | 土壤、池塘、人体等环境参数 |
| 格子配置 | 空格、资源格、危险格、敌人格 |
| 事件配置 | 干旱、消毒、腐败、免疫巡逻 |
| 进化配置 | 耐热、抗毒、快速复苏等节点 |
| 敌人配置 | 捕食者、竞争菌群、免疫单位 |
| 掉落配置 | 每种格子的资源奖励 |

## 2. Unity 中的推荐方式

可以使用：

```text
ScriptableObject
```

保存：

- SpeciesData
- SkillData
- MapData
- TileData
- EvolutionData
- EnemyData
- EventData

## 3. Godot 中的推荐方式

可以使用：

```text
Resource 文件
```

保存：

- species_resource
- skill_resource
- map_resource
- tile_resource
- evolution_resource
- enemy_resource
- event_resource

## 4. 存档和配置的区别

| 类型 | 作用 | 是否随玩家变化 |
|---|---|---|
| 配置数据 | 游戏规则、角色基础属性、地图规则 | 否 |
| 存档数据 | 玩家当前进度、资源、解锁内容 | 是 |

不要把配置数据和存档数据混在一起。

# 十六、存档系统

## 1. 存档内容

| 内容 | 说明 |
|---|---|
| 当前拥有角色 | 解锁了哪些微生物 |
| 培养皿状态 | 各族群恢复进度、公共库存 |
| 资源库存 | 公共库存 + 各角色已分配库存（营养、水分、糖分、矿物质、基因点） |
| 微生物状态 | 族群数量、永久进化、孢子库存、当前状态 |
| 地图进度 | 已解锁地图、探索记录、阶段收益成就、地区长期变量 |
| 图鉴进度 | 已发现资源、敌人、事件和进化 |
| 设置项 | 音量、语言、画质等 |

## 2. 存档原则

| 原则 | 说明 |
|---|---|
| 自动保存 | 每次返回培养皿时保存 |
| 手动保存 | 玩家可主动保存 |
| 防止损坏 | 保存时可使用备份文件 |
| 不保存地图随机过程 | 通常只保存地图结果，不保存完整临时格子 |
| 保存探索中状态可选 | 如果想支持中途退出，需要保存当前地图格子状态 |

# 十七、第一版 MVP 设计

## 1. MVP 目标

第一版目标不是做完整大游戏，而是验证核心玩法是否成立。

验证重点：

```text
翻格是否有趣
移动和蔓延是否清晰
培养皿和地图是否形成循环
地图内进化是否有驱动力
孢子化撤离是否有策略价值
```

## 2. 第一版内容建议

| 模块 | 第一版内容 |
|---|---|
| 角色 | 4 个：芽孢杆菌、蓝细菌、酵母菌、网柄菌 |
| 地图 | 3 张：土壤、淡水池塘、腐烂水果（可反复进入的进化场） |
| 地图形态 | 六边形格子地图 |
| 行动方式 | 每回合 3 点行动点，每个动作消耗 1 点 |
| 初始揭示 | 核心格 + 周围 6 个相邻六边形格 |
| 资源 | 能量、水分、营养、糖分、基因点 |
| 格子类型 | 空格、资源格、危险格、敌人格、进化格、传播格 |
| 敌人 | 捕食者、竞争菌群、环境压力 |
| 孢子 | 保命、主动撤离、复苏 |
| 培养皿 | 真实时间恢复、无配方投喂、角色独立分配、暂不升级 |
| 进化 | 每个角色 3 个基础进化节点；撤离成功才永久保留 |
| 地图目标 | 无固定通关条件；用阶段收益目标引导探索 |

## 3. 第一版角色能力

| 角色 | 第一版能力 |
|---|---|
| 芽孢杆菌 | 芽孢化、厚壁强化、复苏 |
| 蓝细菌 | 光合作用、藻膜扩张、弱光适应 |
| 酵母菌 | 出芽繁殖、发酵代谢、糖分感知 |
| 网柄菌 | 趋化聚集、群体迁移、孢子塔 |

## 4. 第一版地图阶段收益目标

这些目标用于引导探索和结算额外奖励，**不是强制通关条件**。玩家可随时尝试孢子化撤离。

| 地图 | 阶段收益目标示例 |
|---|---|
| 土壤 | 熬过 1 次干旱周期；带回一定能量；解锁耐干燥进化 |
| 淡水池塘 | 占领若干光照格；完成一次传播事件；带回光合相关资源 |
| 腐烂水果 | 在腐败加剧前积累糖分并孢子化撤离；触发发酵相关进化 |

# 十九、关键设计风险

## 1. 移动和蔓延混淆

风险：

```text
玩家不知道自己是在控制核心菌落，还是控制整片菌群。
```

解决：

```text
核心菌落只负责移动和翻格。
蔓延菌群只负责占领和持续收益。
```

## 2. 培养皿过强

风险：

```text
玩家只在培养皿里慢慢恢复，不愿意进地图冒险。
```

解决：

```text
培养皿只能恢复族群，不能进化。
高级资源和高级进化必须来自地图。
```

## 3. 地图资源无限刷

风险：

```text
玩家在低难度地图无限刷资源，破坏成长节奏。
```

解决：

```text
每次进入重新生成。
局内采后不再生。
危险事件随回合推进。
```

## 4. 进化过于数值化

风险：

```text
进化只是 +10% 生命值，缺乏玩法变化。
```

解决：

```text
每个关键进化都应该改变玩法。
例如：可以进入毒素格、可以远距离传播、可以在光照格自动产能。
撤离成功才永久保留，强化“带走成果”的决策。
```

## 5. 第一版内容过大

风险：

```text
角色、地图、技能、事件同时做太多，导致项目失控。
```

解决：

```text
先做 4 角色 + 3 地图 + 6 种格子 + 基础回合制。
验证核心玩法后再扩展。
```

# 二十、最终规则摘要

```text
玩家从培养皿派出一个微生物核心菌落，随机落入六边形地图格子。
地图每次进入重新生成；核心格及其 6 个相邻格默认揭示。
玩家每回合拥有 3 点行动点，通过翻格、移动、采集、蔓延扩大生存空间。
地图是可反复进入的进化场，没有固定通关条件。
局内资源采后不再生；维持消耗随难度与环境成比例增加。
地图中可获得临时进化；必须孢子化撤离成功才永久保留。
孢子化消耗当前能量的 10%（最低 1 点）。
族群数量归零则本次探索失败。
培养皿按真实时间恢复；资源由玩家分配给各角色，互不共享；暂不升级。
游戏采用正常游戏开发模式，使用正式引擎、场景、系统模块、数据配置和存档系统。
```
