## 为什么

《孢子进化》已有较完整的游戏设定，但仓库尚无任何可运行工程。需要先搭一个**可启动的空白跨端壳**，把「培养皿 / 地图」等场景占位与清晰 UI 骨架立住，避免一上来就写玩法逻辑导致结构混乱；并确保同一套界面可在**网页与手机浏览器**中访问。

## 变更内容

- 新增可本地启动的空白前端工程（开发服务器一键跑起）。
- 采用场景化 / 路由化壳层，预留与设定对齐的空场景（主菜单、培养皿、地图占位），**不实现**翻格、回合、进化等玩法。
- 建立响应式布局与基础 UI 区域划分（顶栏信息、主视区、底栏操作），保证手机与网页访问时结构清晰、不堆控件。
- 约定后续玩法逻辑的挂载点（场景容器、系统模块目录），本变更只落空壳与启动链路。
- 不引入原生双端打包流水线的完整实现；第一版以「同一 Web 应用 + 移动端适配」为主，为后续 PWA / Capacitor / 引擎导出留扩展点。

## 功能 (Capabilities)

### 新增功能
- `blank-runtime`: 可安装依赖并启动的空白应用运行时（开发服务器 + 根页面可打开）
- `responsive-shell`: 网页与手机共用的响应式壳层与清晰 UI 分区
- `scene-placeholders`: 与设定对齐的空场景占位与场景切换（无玩法逻辑）

### 修改功能
- （无；仓库尚无既有 `openspec/specs` 能力规范）

## 影响

- 新增前端工程目录与依赖（包管理、构建工具、基础 UI）。
- 新增场景/路由与布局约定，影响后续玩法与引擎/画布接入方式。
- 不改动 `游戏设定/` 文档正文；实现以设定中的场景拆分为参照。
- 本阶段无后端、无存档、无游戏规则代码。
