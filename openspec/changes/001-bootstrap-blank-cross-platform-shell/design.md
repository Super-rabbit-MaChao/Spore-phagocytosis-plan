## 上下文

仓库目前只有 `游戏设定/` 与 OpenSpec 配置，没有可运行工程。设定已明确：培养皿主基地、地图探索、场景切换（主菜单 / 培养皿 / 地图 / 结算等），以及后续可能用正式游戏引擎开发。本变更只交付**空白可启动壳**，玩法逻辑全部后置。

约束：

- 同一入口同时服务**网页与手机浏览器**访问。
- UI 必须分区清晰，避免控件堆叠。
- 不实现回合、格子、进化、孢子化等规则。

## 目标 / 非目标

**目标：**

- 本地 `install` + `dev` 即可打开空白应用。
- 响应式壳：桌面宽屏与手机窄屏都有稳定布局骨架。
- 场景占位：主菜单、培养皿、地图（空），可切换，无逻辑。
- 目录约定便于后续挂玩法模块或替换主视区为画布/引擎视图。

**非目标：**

- 任何游戏规则、数值、存档、敌人 AI。
- 原生 App 商店打包（iOS/Android 正式工程）、后端 API、账号系统。
- 完整美术资源与科普绘本风终态视觉。
- 选定并绑定最终游戏引擎实现（Godot/Unity 等可在后续变更接入）。

## 决策

### 1. 技术栈：Vite + React + TypeScript

| 选择 | 理由 |
|---|---|
| Vite + React + TS | 启动快、生态成熟、易做响应式壳与场景路由；适合“先空壳后挂逻辑”。 |
| 纯 Web 应用 | “手机 + 网页访问”第一版用同一 URL；手机走移动浏览器即可。 |
| 暂不用 Godot/Unity 作为本变更载体 | 设定推荐引擎，但空白壳阶段优先可验证的 Web 启动链路；主视区预留 `GameViewport` 挂载点，后续可嵌入画布或引擎导出页。 |

**替代方案：**

- Godot 直接起项：导出 Web/移动更贴近最终游戏，但空壳阶段工具链更重，UI 壳与文档协作成本高。
- Next.js 全栈：本阶段无服务端需求，过重。
- 纯静态 HTML：难维护场景结构与后续 TS 玩法模块。

### 2. 路由即场景

使用轻量客户端路由（如 React Router）映射设定中的场景：

| 路由 | 场景 | 本阶段内容 |
|---|---|---|
| `/` | 主菜单 | 标题 + 进入培养皿按钮 |
| `/petri-dish` | 培养皿 | 分区占位文案，无恢复/投喂逻辑 |
| `/map` | 地图 | 六边形/探索主视区占位框，无翻格逻辑 |

场景切换只改路由与壳层高亮，不触发游戏状态机。

### 3. UI 分区（防乱）

统一 `AppShell`：

```text
┌─────────────────────────────┐
│ TopBar（标题 / 场景名）      │
├─────────────────────────────┤
│ MainViewport（唯一主内容）   │
├─────────────────────────────┤
│ BottomBar（主操作 1～3 个）  │
└─────────────────────────────┘
```

规则：

- 第一视口只保留品牌/场景名、一句说明、主视区、少量 CTA。
- 禁止在壳层堆统计条、多卡片仪表盘。
- 手机：BottomBar 固定；桌面：可同结构加宽边距。
- CSS 变量定义色板，避免默认紫渐变模板风；本阶段可用简洁中性色。

### 4. 工程目录

建议根目录 `app/`（或 `web/`）：

```text
app/
  src/
    app/           # 路由入口、AppShell
    scenes/        # MainMenu / PetriDish / Map 占位
    styles/        # 全局变量、响应式
    systems/       # 空目录占位（Turn/Resource… 后续）
  index.html
  package.json
```

`systems/` 仅建空 README，声明“禁止在本变更写入玩法”。

### 5. 跨端访问策略（分阶段）

| 阶段 | 做法 |
|---|---|
| 本变更 | 响应式 Web；`viewport` meta；触控友好点击区域 |
| 后续可选 | PWA；或 Capacitor 包壳；或引擎 Web 导出嵌入 `GameViewport` |

## 风险 / 权衡

- [最终可能换 Godot] → 缓解：场景边界与 `GameViewport` 隔离，玩法不写进壳层组件。
- [空壳被误当成可玩 Demo] → 缓解：各场景明确“占位 / 无逻辑”文案。
- [过早引入 UI 组件库导致样式膨胀] → 缓解：本阶段手写少量布局 CSS，不引大型组件库。
- [手机浏览器差异] → 缓解：以现代移动 Chrome/Safari 为验收基线；固定壳高度用 `100dvh`。

## 迁移计划

1. 新增 `app/` 工程与 README 启动说明。
2. 不影响现有 `游戏设定/` 与 OpenSpec 文档。
3. 若废弃本壳：删除 `app/` 即可，无数据迁移。
