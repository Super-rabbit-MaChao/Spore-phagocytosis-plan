# 快进恢复且满员停止

- id: 02
- status: done
- depends: [01]
- maps-to-task: [1.1, 1.2, 2.1, 3.1, 3.2]

## Intent

实现培养皿真实时间恢复：按上次恢复时间戳累计，每现实 10 分钟 +1 族群，达到族群上限后停止。提供仅开发可见的调试快进（必要时一键填满）以便 30 秒内验收，无需真等 10 分钟。

## Verify

约 30 秒内手动确认：

1. 族群未满时，点一次「快进 10 分钟」（或等价调试）→ 族群 +1，且不超过上限
2. 停留在培养皿数秒：在未快进、未到间隔时，族群不无故跳动（无错误连加）
3. 用调试将族群填满至上限（或连点快进至满）后，再快进 → 族群仍为上限，不再增加
4. 地图场景仍无本变更玩法逻辑

## Steps

- [x] 记录恢复用时间戳（如 `lastRecoveryAt`），在培养皿挂载/可见时按流逝时间结算应恢复点数
- [x] 恢复规则：每 `10` 分钟 +1 族群，钳制到 `populationCap`；已满则不再因自动恢复增加
- [x] 增加调试快进（推进 10 分钟或缩短间隔配置，仅开发可见）；可选「填满族群」仅用于上限验收
- [x] 确认达到上限后快进/自动恢复均不再增加
- [x] 按 Verify 走一遍

## Notes

- 默认间隔：现实 `10` 分钟 / +1；验收依赖快进，不要求真人等待
- 离线每日恢复上限（设定中的 50% 缺口）本变更不做
- 投喂与自动恢复共用同一族群上限钳制
- 验证：`pnpm lint` / `pnpm build` 通过；规则测：未满快进 +1、满员快进不变、多间隔钳制到上限。请在 `pnpm dev` 培养皿用调试按钮目视确认。
