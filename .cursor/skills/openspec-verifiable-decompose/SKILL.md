# 可验证拆解（openspec-verifiable-decompose）

把一个阶段目标拆成**可验证竖切**的多文件计划。只规划，不实现。

## 何时使用

- 用户要拆解需求 / 子任务 / 可验证切片
- 用户提到 `plan/`、阶段性推进、最小可验证子任务
- **不要**在本 skill 里写业务代码或连续实现切片

## 硬性规则

1. 每个 plan 文件必须有可观察的 **verify**（约 30 秒内能亲眼确认）
2. **默认多文件**。仅当整段需求已是单个最小可验证阶段时，才允许单文件
3. 优先竖切（端到端一小条可玩/可用效果），禁止「纯脚手架、无可见效果」单独成文件（极薄骨架例外：空场景能打开）
4. 只拆到用户给出的阶段目标为止，不把远期功能拆进来
5. 写出计划后**停止**，等人确认；不自动进入执行
6. 本 skill **不**主动读取或写入 `openspec/changes/`（那是 `openspec-slice-adapter` 的事）。若用户或适配层指定了 `plan/` 路径，则用指定路径

## 如何确定 plan 目录

1. 若用户或调用方给出了明确的 `plan/` 目录 → 使用它
2. 否则 → `<项目根>/plan/`
3. 目录不存在则创建

## 工作流程

1. **确认目标**  
   若目标不清，先问一句：本阶段结束时，什么现象算「做成了」？

2. **只读探测上下文**  
   可阅读现有代码、设定文档、用户指定的材料。不要实现。

3. **拆成阶段切片**  
   - 一个文件 = 一个可独立交付、可独立验证的阶段  
   - 文件内可用 checklist 写更细步骤  
   - 按依赖排序，文件名用稳定序号前缀

4. **写入文件**  
   - 写 `_index.md`（必有）  
   - 写 `NN-slug.md`（默认多个）  
   - 格式见 [slice-format.md](slice-format.md)

5. **展示摘要并停止**  
   列出文件顺序、每个文件的 verify、当前 `current` 指针。等待用户确认，或改用 `openspec-verifiable-execute`。

## 命名

- `_index.md`：总序与进度
- `01-short-slug.md`、`02-...`：两位序号 + kebab-case
- slug 描述可观察结果，如 `01-hex-grid-visible`，不要用 `01-setup-models`

## 反模式

- 按技术层切：先全部数据层、再全部 UI、最后才第一次能看见效果
- 一个巨型 `slices.md` 塞进所有阶段（除非需求本身极小）
- 无 verify 的「准备 / 重构 / 清理」单独成文件
- 拆完后自动开始写实现代码
